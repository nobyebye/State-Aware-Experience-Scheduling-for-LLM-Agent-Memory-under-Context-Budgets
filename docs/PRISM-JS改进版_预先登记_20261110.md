# PRISM-JS 改进版（js2）预先登记（2026-11-10，任何 js2 付费运行之前）

## 1. 改动内容

只改"查询类任务 · 成功执行后"这一层的嵌套删除路径，其余三层（初始·查询、初始·修改、成功后·修改）的路径与开发集搜索数据都沿用原版。

原版路径（成功后，两类任务共用）：exp_rest → exp_top1 → fn_other+fn_predicted → schema+one_stmt+scope → insight → observe+rounds+modify_answer → answer_query+empty_scalar。

改进版路径（仅成功后·查询类）：

| 步 | 本步新增删除 | 累计删除 |
|---|---|---|
| 1 | schema, one_stmt, scope | 规则与表结构 |
| 2 | fn_other, fn_predicted | + 函数说明 |
| 3 | insight | + 洞见 |
| 4 | observe, rounds, modify_answer | + 其余流程规则 |
| 5 | exp_rest | + 次要经验示例 |
| 6 | exp_top1 | + 最相似经验示例 |

answer_query 与 empty_scalar（作答格式规则）不进入改进版路径：原版搜索中删除它们的那一步损失为 +41.6pp。

## 2. 改动依据

- 开发集原版搜索中，成功后·查询类第一步只删 exp_rest，损失估计 +9.09pp（上界 +16.1pp）；继续删更多组后估计损失反而为负。这一非单调模式说明经验示例在作答步骤有作用，而后续步骤的估计受噪声影响。
- 测试集误差分析（事后、探索性）显示，原版 js@8 的损失集中在查询类任务"SQL 已成功但最终答案错误"，且该层原版删除了全部经验示例。改进版的设计受此分析启发，因此改进版在测试集上的结果属于事后改进，论文中与原版结果并列报告并明确标注。

## 3. 流程（scripts/run_js2.sh）

1. 开发集联合消融：js-ref 与 6 个新 js-abl 条件，110 题 × 3 次（2310 次运行），与原版搜索同一模型与配置；js-ref 在同批重跑以保证配对。
2. 策略族：analysis/js2_search.py，λ ∈ {2,4,6,8,10,12,16}，与原版相同的 97.5% 上界与两项多选背包；成功后·查询类用新路径和新批次数据，其余三层用原版搜索数据。
3. 校准：构建集校准部分（203 题 × 10 次），条件为 full 与 λ ∈ {2,4,8,16} 中各不同策略的首个 λ；固定序列非劣检验，δ = 5pp，结果为 λ*。若无 λ 通过则不进行测试。
4. 测试：测试集 114 题 × 10 次，同一批次运行 full、phase_switch、js2@λ*；与原版 js@8（原测试批次）一并报告（analysis/js2_compare.py）。

## 4. 不变的部分

实验代码（src/）不变，代码指纹不变；配置 configs/js2.json 与 default.json 只差 js_table 路径。统计方法与原版相同：按题平均的配对差、题目组整群自助法（B = 10000，种子 20261022）。
