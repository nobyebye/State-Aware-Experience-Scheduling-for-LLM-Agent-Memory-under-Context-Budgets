# 诊断实验：成功执行后整块删除为何提高成功率（2026-11-07 预先登记）

## 目的

测试集上 phase_switch 在“上一步 SQL 成功执行后”的轮次只保留洞见，删除全部相似示例、表信息与 SQL 规则，
成功率高于完整记忆注入与 PRISM。开发集单组消融显示单独删除任何一组都不降低“SQL 正确但答案写错”的比例。
本实验在开发集上检验：好处来自删除哪一部分，以及示例缺少执行结果是否是原因之一。

## 条件（开发集 110 题，每题 5 次，只改变成功执行后的轮次，其余轮次与 full 相同）

| 标签 | 条件名 |
|---|---|
| 参照 | full |
| (a) 删全部示例 | ablate:exp_top1+exp_rest@after_success |
| (b) 删表信息与规则 | ablate:one_stmt+scope+fn_predicted+fn_other+schema@after_success |
| (c) 删表信息与示例 | ablate:schema+exp_top1+exp_rest@after_success |
| (d) phase_switch 的整块删除 | ablate:one_stmt+scope+fn_predicted+fn_other+schema+exp_top1+exp_rest+repair@after_success |
| (e) 示例写出执行结果 | full，配置 configs/obs_examples.json（所有轮次的示例在每条 SQL 后写出 MySQL 结果） |

(e) 的记忆库由 `add-example-observations` 从现有记忆库与构建它的 nomem 运行记录生成，检索文本、条目与 id 不变，
只在示例文本中加入执行结果；生成前逐条核对示例文本与记录重建结果一致。

## 指标

成功率及与 full 的逐题配对差（题目组聚类 bootstrap 95% 区间）；首步 SQL 出错率；查询题中“首步 SQL 结果正确但最终答案错误”的比例；成功执行后轮次的输入 token。
分析脚本：analysis/after_success_diagnosis.py。

## 范围

只用开发集，不使用构建集与测试集，不改变冻结的风险表、记忆库与已运行条件的代码指纹。结果只用于解释机制，不用于修改已在测试集上评估的方法。
